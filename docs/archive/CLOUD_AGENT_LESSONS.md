# 云端 Agent（Hermes 实现）留下的经验

> **面向**：实现下一代云端 Agent（Pi 内核）的人
> **什么时候读**：写云端服务端、审批回环、SSE、派活之前
> **状态**：2026-11-11 归档。Hermes 版云端实现已从主线移除（0.10.0）。本文只留「换掉运行时之后仍然成立」的结论。
> **旧方案的完整正文**：`git show legacy/cloud-hermes-0.9.1:docs/requirements/CLOUD_AGENT.md`（另见分支 `archive/cloud-hermes`）

## 1. 安全边界（换实现不改口径）

单用户前提；云端 Agent 拿整机权限，所以不防「agent 自己提权」，只防三件事：**误操作、外泄、公网扫描打进控制面**。

| 边界 | 结论 |
| --- | --- |
| 云端在独立主机，本地只走协议 | 控制面只监听 loopback，TLS 反代对外；安全组只开 443 |
| 云端零本地授权 | 云端只能发请求；本地动作由本地按「白名单 + 权限档 + 逐次审批」授予 |
| 凭据不进模型上下文与日志 | token 只进主进程 safeStorage；管理密钥只进服务器 `.env`；输出做 redactor |
| 不可逆操作必须人工批准 | 容器后端与审批互斥，不用；`execute_code` 类工具禁用 |
| 审批 fail-closed | 超时 / 通道缺失 / 回执异常 → 一律拒绝，不自动重试 |
| 控制台不得成为提权通道 | **不提供 `always`**；配置写只允许 `approvals.mode` 一个键 |
| 两个暴露面分开治理 | 设备面 = token + 限流；控制台面 = 自己的认证 + IP 白名单 |
| 硬边界只能在主机外 | 云安全组、快照 + 自动备份、provider 额度告警 |

**已知弱点（旧实现承认过，别假装新实现没有）**

- 纯 `sudo <cmd>` 不在危险模式表里，不弹审批。
- `write` / `edit` 类工具没有逐次审批路径；整机权限下可以改自己的配置。
- 没有消费上限 / 预算熔断。
- 系统级 deny 清单（`sudo` / `systemctl` / `crontab` / `authorized_keys` / `iptables` / `ufw` / `useradd` / `chmod 777`）是否启用是运维决策，旧实现默认空。

## 2. 审批语义（四条，缺一条就出事）

1. **fail-closed**：超时、通道缺失、回执解析失败，全部按拒绝处理。
2. **不给 `always`**：一旦允许「永久放行」，审批就不再是安全边界，只是延迟。
3. **回执必须绑 `requestId`**（旧后端还有 `generation`，防 stale）；用合成序号会匹配不上已结算的请求。
4. **审批等待期间挂起看门狗**：工具执行与等人点按钮都不算「模型卡死」，否则 2 分钟就误判 abort。

审批超时旧值是 120s。**云端无人值守下这套是不够的**：`ask` 档在半夜等于一条 120s 后自动拒绝的死路。下一代应当是 `readonly`（deny 不 ask）+ 白名单工作区 + 步数 / 预算上限。

## 3. 协议与流式的坑（会被原样再踩一遍）

| 坑 | 结论 |
| --- | --- |
| 事件流重试 | 按错误分级：4xx 立即失败，只有网络 / 5xx / 中断才退避重试；否则白烧退避并误报「多次中断」 |
| 断线重连 | 用游标（旧实现是 `last_seq`，顶到 int32 上限只收增量）续传，不要整段重放 |
| 收尾整段替换 | 实时流干净跑完时只用历史**核对审计**，不要推全量 parts —— 整段替换会把请求期间刚上屏的消息顶掉 |
| 历史分页 | `offset` 从 0 数，最新消息在尾部；「取最新一页」要先探一页、满页才算尾部，两跳 |
| 幂等 | 每轮带幂等键；进程重启后靠 `resolve-unknown` 收敛「服务端还在跑、本地以为死了」 |
| 插话状态 | 要区分「已投递 / 在途 / 本轮结束仍未投递」，只显示成功会骗人 |
| 工具结果预览 | 剥掉 ANSI；预览长度上限要有截断标记（旧值 4KB） |
| 终态保真 | `usage` / provider·model / `partial` / `interrupted` 都要落到脚注，截断与打断不能显示成正常结束 |

## 4. 设备身份

- **token → deviceId**，不要把主机名当身份（会重名、会被改、含个人信息）。`author` 只做记忆归属，不注入 prompt。
- 心跳 30s 一拍，90s 无认证请求判离线；被撤销立即停并推事件。
- 配对用**一次性连接码**；管理密钥永不离开服务器，桌面端只存设备 token（`enc:` + safeStorage）。
- 同设备重新配对：旧 token 立即失效。注销只清自己的设备凭据，不删服务端数据。

---

## 5. 派活（若下一代保留这个能力）

- 状态机三段：`working` / `input-required` / `completed`（+ 失败与取消），**进度只有云端会话一个出口**，不做推送、不做逐条直播。
- 幂等：同一个 task 重发不重跑；取消原因要透传给调用方；过期要有明确原因。
- 租约重投**只投原设备**——绑死在 claim 它的设备上，跨设备重投是语义错误，不是功能缺失。
- 单设备并发 1：两个会话同时写一棵树的结果是零收益的坏账。
- 「关掉派活」必须真的 abort 正在跑的任务，不只是断连。
- 本地反问（`input_required`）必须能让本机 Agent 问云端、云端答，而不是问人。

---

## 6. 部署坑（旧实现踩过的，逐条都是时间）

- **不要用 root 跑 CLI**：会因目录属主不匹配拒绝执行，且服务仍跑旧代码，排查成本极高。
- 卸载插件**不会**删它的数据目录（设备表、审计都在里面），要手动删。
- SSE 反代要关缓冲（Caddy `flush_interval -1`）；WS 升级头不转发、Host 要改写。
- 反代只放行白名单路径，其余明确 `404`，不要透传。
- 上游的「多路复用」形态可能让 **profile 的 `.env` 与 api_server 都不进宿主进程** → 密钥缺失 + 上游 401，插件变成空壳。升上游前先跑一遍基线，别在迁移上赌。

## 7. 验收清单要重跑的部分

旧清单 22 条（配对 10 条 + 功能 22 条）。下一代至少要重跑这些语义：冷启动列会话、发指令流式、审批拒绝、审批超时自动拒绝、断线 / 重启状态一致、断线补齐、幂等键、未结算核对、云端零本地文件能力、与工作区隔离、反代穿透（SSE / WS / Host / 强制 TLS）、无遥测出网复核。

平台相关的两条（拆窗、屏幕接管）属于后置能力，不属于验收阻塞项。
