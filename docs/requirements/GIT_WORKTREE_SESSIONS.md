## 1. 背景与目标

### 1.1 现状

- 一个逻辑工作区对应一个 `AgentManager` 和一个固定 cwd；同一工作区内的多个会话共享同一份 checkout。
- 应用没有分支、工作树的概念；文件树、编辑器、diff、终端都以工作区根为基准。
- Agent 可以通过 bash 执行任意 git 命令，但应用不感知，也不会刷新状态。

### 1.2 目标

- 在同一个仓库里，多个会话可以**并行修改文件**；需要时各自绑定不同的工作树，从而落在不同的分支里。
- 能简单地切换分支、合并分支。
- 不给 Agent 增加任何硬限制。

### 1.3 本轮讨论确立的结论

1. **会话只有一个"当前工作树"**，没有"工作树模式"这种额外状态。工作树是会话的一个属性，默认是主工作树，也可以切换到一个链接工作树。
2. **需要不同分支时，必须绑定不同的工作树**。一个工作树只有一个 HEAD；多个会话绑定同一个工作树，就共享同一个分支、同一份文件和同一个暂存区。
3. **隔离与分支独占由 git 自己提供**。同一分支不能同时被两个工作树检出；不同工作树之间文件互不可见；冲突由 git 产出。应用不需要实现只读会话、分支归属锁或保护分支。
4. **cwd 不能在工具调用中途切换**。切换当前工作树需要重建会话运行时，只能在轮次边界执行。
5. **一个工作区就是一个 Git 仓库**。需要同时处理多个仓库时，打开多个工作区；不支持一个工作区里包含多个仓库。
6. **嵌套仓库按普通文件处理**。工作区内部再出现 `.git` 的目录，不被单独发现、选择和切换。
7. **提交与合并只走对话**。不提供提交框或合并框；由 Agent 在对话中执行并说明。
8. **Git 视图只读**。提供 GitLens 风格的只读视图，所有写操作通过对话或切换工作树完成。

### 1.4 状态标记

- `[确认]`：本轮讨论中用户明确确认。
- `[确认·v1.7]`：v1.7 已确认，本轮讨论沿用，未重新讨论。
- `[推断]`：由确认项推导出的必要行为，仍需用户点头。
- `[待确认]`：尚未决定。

## 2. 术语

| 术语 | 定义 |
| --- | --- |
| 逻辑工作区 | 用户打开的单个 Git 仓库目录；会话、设置、文件树的容器。多工作区仍然支持，每个工作区一个仓库。 |
| 主工作树 | 仓库原本的那份 checkout，位于工作区根。永不删除。 |
| 链接工作树 | 通过 `git worktree add` 创建的额外工作目录，拥有独立的工作文件和 HEAD。 |
| 当前工作树 | 一个会话此刻绑定并以其作为 cwd 的工作树；默认是主工作树。 |
| 绑定 | 会话与一个工作树的对应关系；持久化在 `session-git.json`。 |
| 共享工作树 | 多个会话绑定同一个工作树；它们共享分支、文件、暂存区和 HEAD。 |
| 托管工作树 | 由应用创建的链接工作树，应用负责在不再被任何会话绑定后清理。 |
| 外部工作树 | 用户在应用外创建的链接工作树；应用只允许绑定，不自动删除。 |
| 分支 | 属于工作树的属性，不是会话的属性。会话"当前分支"就是其当前工作树的 HEAD。 |
| 基分支 | 创建链接工作树时选择的分支或提交；只用于创建，不影响默认合并目标。 |
| 目标分支 | 合并的目标；默认是主工作树当前的 HEAD，用户可指定。 |
| 嵌套仓库 | 工作区内部另一个带有 `.git` 的目录；本版按普通文件处理。 |
| 轮次边界 | 一次 Agent 运行（一轮）结束、没有在途工具调用的时刻，对应 SDK 的 `agent_settled`。 |
| pending 切换 | 已收到切换工作树请求并完成准备工作、但尚未在轮次边界生效的中间状态。 |

## 3. 核心模型

- **一个工作区 = 一个 Git 仓库。** 打开仓库根即进入单仓模式；非 Git 文件夹按 GIT-106 处理；多工作区通过打开多个仓库实现。
- 仓库有且只有一个**主工作树**，可以有任意多个**链接工作树**（应用创建的记为托管，用户创建的记为外部）。
- 每个会话有且只有一个**当前工作树**：
  - 默认是主工作树；
  - 创建会话时可以选择主工作树、新建一个链接工作树，或绑定一个已有链接工作树；
  - 运行中可以切换，在轮次边界生效。
- **多个会话可以绑定同一个工作树。** 它们共享分支、文件、暂存区和 HEAD：一个会话的改动、提交、切分支，另一个立刻可见。应用不禁止，界面必须标明"共享"。
- **分支属于工作树，不属于会话。** 要让两个会话在不同分支上工作，必须让它们绑定不同的工作树；同一个工作树无法同时检出两个分支。
- 应用创建的工作树是托管的、可回收的；外部工作树只允许绑定，永不自动删除。主工作树永不删除。
- 应用不实现只读会话、分支归属锁、保护分支、提交审批。
- 非 Git 工作区直接编辑文件，不创建工作树，不提供 Git 功能。

## 4. 功能需求

### 4.1 工作区与打开

**GIT-101 `[确认]` 单仓工作区**  
单仓模式下，工作区根是一个 Git 仓库，该仓库就是工作区；也允许打开非 Git 文件夹，此时不提供 Git 功能（GIT-106）。多工作区（同时打开多个仓库）仍然支持；本版不支持的是"一个工作区里包含多个仓库"。

**GIT-102 `[推断]` 打开规则**  
打开工作区时判定一次，不在运行期做仓库发现：

- 打开的是仓库根：正常进入单仓模式。
- 打开的是仓库子目录：向上找到 `.git`，提示"这个目录属于仓库 X，以仓库根打开吗？"；用户拒绝则按非 Git 工作区处理。
- 打开的是链接工作树：提示以该仓库的主工作树打开；用户拒绝则按普通目录处理，不创建嵌套工作树。
- 打开的是 bare 仓库：没有工作文件，提示不支持并要求打开普通仓库。
- 打开的不是仓库、但下一层恰好一个仓库：提示"以这个仓库为工作区打开"。
- 下一层有多个仓库：提示"本版本不支持多仓工作区，请打开具体仓库"，不自动选择。

**GIT-103 `[推断]` 嵌套仓库按普通文件**  
工作区内部出现另一个独立仓库时，不发现、不选择、不切换，按普通文件处理。外层 `git status` 中它可能是未跟踪目录或 gitlink；启动时检测到可以提示一句"检测到嵌套仓库，本版本不单独管理"，不阻断。

**GIT-104 `[确认·v1.7]` 子模块不支持**  
检测到 `.gitmodules` 时提示：链接工作树里子模块目录为空，需要用户自己执行 `git submodule update --init`。应用不递归管理子模块内的 Git 操作，也不保证其完整语义。

**GIT-105 `[推断]` 工作树位置与排除**  
托管工作树位于 `{workspace}/.pi-workbench/worktrees/<worktreeId>/`。通过 `.git/info/exclude` 排除，不修改受版本控制的 `.gitignore`；文件树、文件监听和主工作树的 `git status` 都排除该目录。

**GIT-106 `[确认·v1.7]` 非 Git 工作区**  
打开的不是 Git 仓库、且用户拒绝切换到仓库根时，直接编辑文件；不创建工作树，不提供 Git 功能。

### 4.2 会话与工作树绑定

**GIT-110 `[确认]` 当前工作树，默认主工作树**  
新建会话默认绑定主工作树：cwd 为仓库根，Agent 的读写直接落在主工作树。会话头部必须显示当前工作树；绑定主工作树或与其他会话共享时，要明确标注"改动落在主工作树"或"与他人共享工作树"。  
同一个工作树同一时间只有一个 HEAD 和一个检出分支；绑定同一工作树的所有会话必然处于同一分支，不可能各自在不同分支上工作。需要不同分支时，必须让它们绑定不同的工作树。

**GIT-111 `[确认]` 创建会话时选择工作树**  
新建会话时可以选择：

- 主工作树（默认）；
- 新建一个链接工作树（立即创建并绑定，cwd 直接设为它，不需要中途重建）；
- 一个已有的链接工作树（包括用户创建的外部工作树）；绑定后使用该工作树的分支与文件，如果它已被其他会话绑定，则与它们共享。

选择已有工作树时，如果它正被其他会话绑定，界面提示会共享；Agent 自动选择时优先复用空闲工作树（GIT-168）。

**GIT-112 `[确认]` 运行中切换工作树**  
运行中的切换记录为 pending，在 `agent_settled` 边界重建运行时后生效。工具调用中途不得重建会话。  
切换由用户或 Agent 自行决定，应用不弹窗、不询问；Agent 应在对话中说明要切换到哪个工作树及其原因。

**GIT-113 `[推断]` 新建链接工作树**  
创建托管工作树时执行：

```
git worktree add -b pi/<worktreeId> <worktreePath> <base>
```

- `base` 默认取创建时主工作树的 HEAD；detached HEAD 时取当前提交；用户可在创建前从分支列表改选。
- `worktreeId` 由会话 id 前 8 位加序号组成，保证同一会话多次创建不冲突。
- 工作树路径由 `worktreeId` 推导，重启后保持稳定。

**GIT-114 `[推断]` 幂等**  
同一会话重复绑定当前工作树：只返回 `already`。目标工作树已存在、分支已存在时视为"已具备"，不报错。

**GIT-115 `[推断]` 不移动主工作树的未提交改动**  
绑定或创建链接工作树不 stash、不搬移主工作树的未提交改动。新工作树从 `base` 的提交创建，用户的改动原地保留。

**GIT-116 `[推断]` 绑定与工作树记录持久化**  
写入 `{workspace}/.pi-workbench/session-git.json`，全部使用工作区相对路径，原子写入。至少记录：

- 每个工作树：路径、是否托管、创建者会话、分支、基分支、创建时间、安装依赖时的 lockfile 哈希；
- 每个会话：当前工作树的键。会话关闭时删除该会话的绑定记录；工作树记录保留到回收。

与 `chat-tabs.json`、`editor-tabs.json` 同生命周期：关闭工作区、退出应用都不删除。

**GIT-117 `[确认]` 绑定主工作树不做隔离**  
会话可以直接在主工作树中工作；此时与用户自己的编辑、以及所有同样绑定主工作树的会话共享同一份 checkout，风险由用户承担，界面必须标明。

**GIT-118 `[确认]` 链接工作树的依赖安装**  
每个链接工作树独立安装依赖，采用包管理器的内容寻址存储（Node 优先 pnpm store + 硬链接；bun 用 clonefile/hardlink；npm/yarn 共享缓存），不共享整棵 `node_modules`。  
首次创建或首次复用一个尚未安装依赖的链接工作树时，在后台执行项目对应的安装命令（如 `pnpm install --frozen-lockfile`），在会话头部显示"依赖安装中 / 已就绪 / 失败"。冷缓存时才需要下载，热 store 下通常是秒级到几十秒；安装完成前不阻塞读写文件。安装失败不阻塞会话，由 Agent 在对话中说明原因和建议。  
复用已有工作树且 lockfile 未变化时跳过安装；lockfile 变化时重新安装。  
不可再生的 gitignored 文件（`.env`、本地配置）按可配置清单从主工作树复制；`node_modules`、构建产物、缓存不复制。

**GIT-119 `[确认·v1.7]` 空仓库**  
没有第一次提交的仓库无法创建链接工作树。会话只能绑定主工作树；产生首次提交后，新建会话才能创建或绑定链接工作树；已有会话不自动迁移。

### 4.3 轮次边界切换

**GIT-120 `[确认]` 切换只在轮次边界生效**  
重建会话运行时只能在 `agent_settled`（没有在途工具调用）时执行。工具调用中途不得销毁当前 `AgentSession`。

**GIT-121 `[推断]` 状态机**

```
idle ──切换请求──▶ pending ──agent_settled──▶ applying ──成功──▶ idle（cwd 已换）
                      │                          │
                      │                          └──失败──▶ failed（保留 pending，可重试）
                      └──进程退出──▶ 重启后按持久化绑定直接以目标工作树打开
```

`pending` 只存在于内存，不落盘。新建的工作树在请求时已经创建并写入绑定文件，因此进程退出不会丢失准备结果。

**GIT-122 `[推断]` 重建内容**  
在边界处依次执行：拿会话锁 → 解析目标工作树 → `dispose` 旧 `AgentSession` → 用同一个会话文件 `open` 并覆盖 cwd → `createAgentSession({ cwd: 目标工作树 })` → 重新挂载扩展、重新订阅事件 → 写一条可见记录 → 清 `pending` → 放行排队消息 → 通知渲染进程。历史消息不丢失；per-session 状态按 sessionId 存放，不受影响。  
如果目标工作树与当前工作树相同（例如两个会话共享同一路径），不需要重建。

**GIT-123 `[推断]` 同一轮内的写保护**  
`pending` 期间，写类工具（`write` / `edit`）返回"切换尚未生效，本轮不要写入"。`bash` 不做拦截（Agent 可以继续读、跑查询；写操作由模型按工具描述自行停下）。这是竞态保护，不是对 Agent 的策略限制。

**GIT-124 `[推断]` 切换记录**  
切换完成后向会话追加一条可见记录（工作树、分支、是否共享），并在聊天中显示对应的 trace 事件，不依赖模型记忆。

**GIT-125 `[推断]` 重建期间的消息排队**  
重建期间到达的用户消息和排队消息必须等待，不得用旧 cwd 执行下一轮。

**GIT-126 `[确认]` 本轮收尾方式**  
v1 采用软收尾：本轮自然结束，模型看到工具返回后自行停止，边界处再切换。  
硬收尾（工具返回后主动 `abort()`，边界重建后用 `followUp` 自动开下一轮）保留为后续选项。

**GIT-127 `[推断]` 切回主工作树或其他工作树**  
会话可以切回主工作树或其他工作树；之前绑定的链接工作树保留，未提交改动留在原工作树，不自动 stash、不删除。该工作树会在会话关闭或应用启动时按 GIT-150 / GIT-152 回收。

### 4.4 分支

**GIT-130 `[确认]` 在工作树内切分支**  
分支切换发生在会话当前工作树内。它影响**所有绑定该工作树的会话**以及用户在这个工作树里的编辑；不影响其他工作树。界面必须提示这一点。

**GIT-131 `[推断]` 分支占用冲突**  
目标分支已被另一个工作树检出时 git 会拒绝。界面提供三个出口：新建分支、跳到占用它的会话、取消切换。应用不强制抢占。

**GIT-132 `[确认·v1.7]` 脏改动处理**  
切分支时若存在未提交改动，由 git 自身拒绝覆盖。应用不自动 stash；在对话中说明冲突并让用户选择提交、stash、放弃改动或取消（对话形式，不弹窗）。

**GIT-133 `[推断]` 远程分支**  
分支列表包含本地分支和远程分支；选择远程分支时创建本地跟踪分支。

**GIT-134 `[推断]` 主工作树切分支独立**  
应用不自动切换主工作树的分支；主工作树的分支只由用户显式操作。切换结果会影响所有绑定主工作树的会话，但不影响链接工作树。

### 4.5 提交与合并

**GIT-140 `[确认]` 默认合并目标**  
默认合并目标是**主工作树当前的 HEAD**。用户显式指定其他分支时，按指定分支合并。基分支只用于创建工作树，不再是默认合并目标。  
目标分支必须已经在某个工作树中检出；如果没有任何工作树检出它，Agent 提示用户先把主工作树切换到该分支（或指定其他目标），不自动切换用户的 checkout。  
主工作树处于 detached HEAD 时没有默认目标分支；此时必须由用户指定目标分支，未指定则提示。

**GIT-141 `[推断]` 合并执行位置**  
合并必须在检出了目标分支的工作树里执行。应用先确认目标分支所在的工作树，再在那里执行。

**GIT-142 `[确认]` 并发合并由 git 自己互斥**  
合并由 Agent 在对话中执行。同一目标分支的并发合并会在同一个工作树里竞争 git 的 `index.lock`：后到的操作直接失败并返回明确错误；Agent 看到错误后等前一个合并结束再重试，或向用户说明。应用不额外维护合并队列。  
不同目标分支的合并在不同工作树中进行，互不影响。

**GIT-143 `[确认·v1.7]` 冲突处理**  
合并冲突交给 Agent 在对话中处理，不静默选择一方，不提供冲突审核 UI。

**GIT-144 `[确认·v1.7]` 合并策略与清理**  
默认使用 merge commit，保留该工作树分支的提交序列；用户明确指定时才使用 squash 或 rebase。合并完成后不自动删除分支或工作树。

**GIT-145 `[确认]` 合并前置检查**  
目标工作树有未提交改动、目标分支被其他工作树占用时，由 Agent 在对话中提醒风险，不阻塞合并，也不自动 stash、不自动切换。

**GIT-146 `[确认]` 提交只走对话**  
提交由 Agent 在用户明确要求时执行。提交前列出将要提交的文件，提交信息由 Agent 起草并在对话中给出，用户可要求修改。应用不自动提交。  
如果当前工作树被多个会话共享，提交会包含其他会话尚未提交的改动；Agent 必须在提交前说明这一点。

**GIT-147 `[确认]` 不提供提交框或合并框**  
工作区界面不提供常驻的提交框、合并按钮或合并对话框；提交与合并都通过 Agent 在对话中执行并反馈结果。Git 视图保持只读。

**GIT-148 `[确认·v1.7]` Git 优先**  
对 Git 仓库中已跟踪文件的修改必须直接写入工作树，并能在 `git diff` 中看到；不要求通过 `git apply` 或 Git 命令来编辑文件。未跟踪、忽略、二进制和大文件允许直接写入，但必须在工作区变更视图中可见。

**GIT-149 `[确认·v1.7]` 提交身份与签名**  
提交使用用户自己的 Git 身份；默认不添加 Co-Authored-By；签名和 hooks 遵循用户的 Git 配置。

### 4.6 生命周期

**GIT-150 `[确认]` 关闭会话与工作树回收**  
关闭会话时先解除绑定，然后执行一次工作区级回收：

- 仍有其他会话绑定的工作树：保持原样。
- 托管且没有任何会话绑定的工作树：要求干净——干净则删除（空分支一并删除）；有未提交改动时在对话中处理（stash 保留或显式丢弃），处理干净后再删除。
- 外部工作树：只解绑，永不自动删除，未提交改动原样保留。
- 主工作树：永不删除。

关闭会话时同时终止该会话的会话终端；工作区终端不受影响。

**GIT-151 `[推断]` 重启恢复**  
应用重启后按 `session-git.json` 恢复会话与工作树的绑定；托管工作树缺失时按记录重建（路径稳定）；存在对应 stash 时提示是否 apply，不自动应用；打开中的编辑器标签与终端状态按现有机制恢复。

**GIT-152 `[确认]` 崩溃清理**  
启动时先执行 `git worktree prune`，再对照 `session-git.json` 与 `.pi-workbench/worktrees/` 下的目录扫描：

- 没有任何会话绑定、且是托管的孤儿工作树：干净的直接删除；有未提交改动的列出让用户处理。
- 外部工作树永不自动删除；失去绑定的外部工作树只从记录中移除。

**GIT-153 `[确认]` 只自动清理空分支**  
托管工作树被删除时，如果它的分支没有任何新提交，自动删除该分支；有提交的分支一律保留，应用不做其他自动清理。合并后也不自动删除分支。共享工作树的分支在其他会话仍绑定时不删除。

**GIT-154 `[确认·v1.7]` detached HEAD**  
创建链接工作树时若主工作树处于 detached HEAD，从当前提交创建该工作树的分支，不询问用户。

**GIT-155 `[推断]` 删除会话**  
删除会话与关闭会话同样先解除绑定、按 GIT-150 处理工作树；删除本身沿用现有的二次确认流程。

**GIT-156 `[推断]` 主工作树与外部工作树不可回收**  
主工作树永不删除；外部工作树永不由应用删除。应用只清理自己创建的托管工作树。

### 4.7 视图与终端

**GIT-160 `[确认]` 视图跟随会话的当前工作树（换根重载）**  
文件树、编辑器标签、diff 视图共用一套视图，根跟随当前活动会话的当前工作树；终端按会话切换（GIT-163）。切换会话前，先把当前会话的未保存改动落盘到它的当前工作树（沿用自动保存，切换时立即 flush），然后切换到对应 root 并重新加载文件树与编辑器；撤销栈、滚动位置不保证跨会话保留。每个会话的打开文件列表按会话保存，切换时恢复。

**GIT-161 `[确认]` 编辑器重载**  
切换 root 或切换分支后，编辑器里的旧缓冲必须重载或明确提示。有未保存内容时先按自动保存落盘到当前工作树；保存失败再提示重试、丢弃或取消切换，禁止把旧分支的内容静默写回新分支。

**GIT-162 `[推断]` 文件监听**  
监听主工作树和当前会话的工作树。checkout 会触发大量文件事件，需要抑制并整体刷新，避免事件风暴。

**GIT-163 `[确认]` 终端分两类**  
- **会话终端**：每个会话拥有自己的终端实例，cwd 默认为该会话当前工作树；切换会话时显示对应会话的终端，不同会话的终端互不影响。
- **工作区终端**：用户手动使用、不绑定会话的终端属于工作区，切换会话时保持不变，cwd 默认为仓库根。  
Agent 的 bash 工具不使用这两类终端，它在会话 cwd 中直接执行。

**GIT-164 `[确认·v1.7]` 会话头部状态**  
显示当前工作树（主工作树 / 链接工作树名称）、分支、是否与其他会话共享、未提交改动数量、ahead/behind。

**GIT-165 `[推断]` 主工作树入口**  
会话头部提供工作树切换入口：可以在主工作树、已有链接工作树、新建工作树之间切换；默认视图跟随当前会话的工作树。

**GIT-166 `[推断]` 嵌套仓库显示**  
文件树中嵌套仓库按普通目录显示，不提供单独的仓库操作或状态。

**GIT-167 `[确认]` Agent 的工作树上下文**  
每轮开始时向 Agent 注入：

- 当前工作树：路径、分支、共享的会话数、脏文件数；
- 其他工作树：路径、分支、是否被其他打开会话绑定、是否托管；脏文件数和 ahead/behind 按需刷新。

不注入会话 id 或"哪个工作树属于哪个会话"，避免把会话关系暴露给模型；Agent 也可以自行执行 `git worktree list`。共享状态用于提醒 Agent：当前工作树里的提交可能包含其他会话的改动，切换分支会影响那些会话。  
注入的是快照；真正的占用判定由主进程在绑定时原子完成（GIT-168）。  
其他工作树的脏状态可以按需刷新（例如只在用户打开 Git 视图或需要复用时运行 `git status`），避免每轮对所有工作树执行状态检查。

**GIT-168 `[确认]` 工作树复用与占用判定**  
- 需要隔离时优先复用**没有被其他打开会话绑定**的链接工作树，干净的工作树优先；没有可用工作树时才新建。
- 绑定由主进程原子判定。注入列表里显示空闲、但绑定时已被其他会话占用：返回 `taken`，Agent 改用新工作树。
- 复用有未提交改动的工作树时，Agent 必须在对话中说明会带上这些改动，由用户决定继续使用还是新建。
- 主工作树不作为自动复用的候选；只有用户显式选择时才绑定，避免自动占用用户自己的 checkout。
- 托管工作树和外部工作树都可以复用；外部工作树仍然永不自动删除。

### 4.8 授权与反馈

**GIT-169 `[确认·v1.7]` Agent 的 Git 能力**  
Agent 具备完整的 Git 能力：读取 status / diff / log / show / blame / branch / remote / stash；本地写 add / commit / amend / branch / switch / delete / merge / rebase / cherry-pick / revert / reset / clean / stash / tag；远程 fetch / pull / push / force push。  
这些操作通过 bash 或对话执行，应用不额外拦截；结果必须反馈到会话和 Git 视图。

**GIT-170 `[确认·v1.7]` 不新增 Git 审核弹窗**  
Git 操作不引入独立的审核弹窗。授权由对话指令决定；ask 模式下会覆盖文件改动的 Git 操作沿用现有审批，commit/push/创建或切换分支不弹窗；readonly/plan 禁止 Git 写操作。

**GIT-171 `[确认·v1.7]` 文件写入审批保留**  
文件写入和命令执行的现有审批机制保留，操作系统的权限申请也保留。

**GIT-172 `[确认]` 不额外限制**  
不设置保护分支、不禁止 force push、不强制 PR。push/force/目标分支由用户指令和仓库配置决定；应用不拦截，但必须在结果中明确反馈风险后果。

**GIT-173 `[确认·v3.5]` 外部操作可见**  
外部终端或 Agent 自己执行的 git 操作由主进程的 `.git` 文件监听实时同步（HEAD / refs / index 变化，约 0.3–0.5 秒内反映到 Git 视图），取代原“每轮结束重读 HEAD 与 status”的方案；共享工作树上的变化同时反映到所有绑定它的会话头部。  
如果当前工作树被外部删除或移动，应用停止该会话的写入并提示重新选择工作树。

**GIT-174 `[确认·v1.7]` 凭据**  
使用系统 Git 凭据（SSH agent / credential manager）；应用不保存、不记录、不向模型暴露凭据。

### 4.9 Git 视图（只读）

**GIT-180 `[确认]` 左侧边栏的只读 Git 视图**  
在工作区左侧边栏提供独立于聊天面板的只读 Git 视图，与文件树以 tab 切换；能力和呈现参考 GitLens。视图不承载任何 Git 写操作。

**GIT-181 `[推断]` 视图内容**  
至少显示：

- 本地分支、远程分支、tags、stashes、所有工作树（主工作树、托管、外部）；
- 每个分支的提交历史；
- 各工作树的当前状态；
- 未提交改动（staged / unstaged / untracked），默认显示当前会话的工作树，可按工作树过滤。

列出工作树前执行 `git worktree prune`，避免显示失效记录。

**GIT-182 `[推断]` 提交详情与比较**  
支持：

- 提交详情：作者、时间、消息、文件列表、逐文件 diff；
- 按分支、作者、时间、消息搜索和过滤；
- 分支之间、提交之间的比较。

**GIT-183 `[确认]` 远程与 CI 状态**  
显示远程 ahead/behind、PR/MR 状态、CI 状态。PR/MR 和 CI 支持 GitHub，需要用户配置 GitHub 访问令牌（沿用现有 `safeStorage` 加密存储）；令牌配置在应用级设置（与现有 API 配置同一页），不按工作区配置；非 GitHub 远程或未配置令牌时显示"不可用"，不阻塞本地 Git 操作。  
ahead/behind 与远端引用由后台定时 fetch 自动更新：每 60 秒一次，另在应用启动、窗口重新聚焦、打开 Git 视图时补一次（最小间隔 15 秒，同一仓库串行）；手动刷新为 fetch 后重读。fetch 只更新远端引用，不合并、不修改工作区；认证失败时暂停自动 fetch 30 分钟，手动刷新仍可用。

**GIT-184 `[确认]` 视图只读**  
Git 视图不提供 checkout、merge、rebase、cherry-pick、revert、tag、删除分支等写操作。写操作通过 Agent 对话或切换工作树完成。

**GIT-185 `[推断]` 大仓库性能**  
必须支持分页、懒加载和过滤，不能因加载全部历史而卡死。默认加载范围在设计中确定。

**GIT-186 `[推断]` 不显示会话标记**  
提交图不标注"哪个分支属于哪个会话"；会话的当前工作树、分支和共享状态在会话头部显示。

**GIT-187 `[确认]` 不提供按文件/行的历史**  
不提供文件历史、行历史等按文件或按行的历史视图；会话内的单轮 diff 与 Git 视图的提交详情已经覆盖查看需求。

### 4.10 全局操作与上下文

**GIT-190 `[确认]` 全文搜索跟随当前工作树**  
文件搜索（`workspace:searchFiles` 等）以当前活动会话的工作树为根，不搜索主工作树或其他工作树的内容；用户切到主工作树视图时，搜索范围随之切换。

**GIT-191 `[确认]` 聊天上下文路径基准**  
附加打开文件、引用选区等聊天上下文，路径和内容都以当前活动会话的工作树为基准。切换工作树后，旧上下文保留原始绝对路径；原文件不存在时标记失效，不静默映射到新工作树的同名文件。

## 5. 验收场景

1. 两个会话分别绑定不同的链接工作树，并行修改同一文件，互不干扰；分别提交后依次合并，冲突在对话中解决。
2. 两个会话都绑定主工作树：界面显示"共享工作树"；一个会话切分支，另一个会话和工作区视图同步变化。
3. 新建会话时选择"新建链接工作树"：会话创建后 cwd 即为该工作树，不需要重建。
4. 新建会话时选择一个已被另一个会话绑定的链接工作树：绑定成功，界面显示共享状态；两个会话共享分支和文件。
5. 运行中的会话切换到另一个工作树：请求在当前轮结束后生效，下一轮 cwd 正确，历史消息不丢失。
6. 同一轮内请求切换后继续写文件，`write` / `edit` 被拒绝并收到可操作的原因。
7. 在共享工作树里切换分支：所有绑定该工作树的会话头部同步更新，并提示影响范围。
8. 切换分支时目标分支被另一个工作树占用：git 拒绝，界面给出新建分支、跳转、取消三个出口。
9. 合并默认目标为主工作树当前分支；用户指定一个没有被任何工作树检出的分支时，Agent 提示先切换主工作树，不自动切换。
10. 两个会话同时合并到同一分支：后到的操作收到 git 锁错误，由 Agent 重试或说明；内容冲突交给 Agent 处理。
11. 关闭有未提交改动的会话，且它是工作树的最后一个绑定：先在对话中 stash 或显式丢弃，处理干净后删除托管工作树；分支保留；空分支删除。
12. 关闭一个与他人共享工作树的会话：只解绑，工作树、分支和未提交改动保持不变。
13. 关闭最后一个绑定外部工作树的会话：只解绑，工作树永不自动删除。
14. 应用重启后按绑定恢复；托管工作树缺失时重建，路径不变。
15. 崩溃后启动：清理干净的无主托管工作树；脏的列出等待处理；外部工作树不动。
16. 空仓库：会话只能绑定主工作树；产生首次提交后新建会话可以创建工作树。
17. 切换会话时文件树、编辑器、终端、diff 跟随该会话的工作树；未保存改动先落盘到原工作树。
18. 每个会话拥有自己的终端；切换会话时显示对应终端；工作区终端保持不变。
19. 打开仓库的子目录：提示"以仓库根打开"；拒绝后按非 Git 工作区处理。
20. 打开一个父目录：里面只有一个仓库时提示以该仓库为工作区打开；有多个仓库时明确提示不支持并停止。
21. 工作区内嵌套另一个仓库：按普通文件显示，不提供独立的仓库操作。
22. 包含子模块的仓库：创建链接工作树后提示子模块为空，需用户自行初始化。
23. Git 视图展示分支、所有工作树、提交历史、未提交改动；点击提交查看文件列表与逐文件 diff；不提供任何写操作。
24. Git 视图显示 GitHub PR/CI 状态；未配置令牌时显示"不可用"，不影响本地操作。
25. Agent 在每轮开始时能看到当前工作树、分支、共享状态，以及其他工作树的路径和分支；看不到会话归属。
26. Agent 需要隔离时优先复用一个空闲工作树（跳过依赖安装）；被其他会话占用的工作树不复用，改用新建；复用一个有未提交改动的工作树前先向用户说明。
27. 两个会话同时尝试绑定同一个空闲工作树：主进程原子判定，只有一个成功，另一个收到 `taken` 并改用新工作树。
28. 当前工作树被外部删除或移动：会话停止写入并提示重新选择工作树，不会把文件写到错误位置。
29. 主工作树处于 detached HEAD 时发起合并：没有默认目标分支，Agent 要求用户指定分支。

## 7. 与上一版的差异

### 7.1 删除或改变的需求

| 上一版条目 | 处理 | 原因 |
| --- | --- | --- |
| "主工作树模式 / 工作树模式" | 删除 | 会话没有模式，只有一个当前工作树 |
| "会话分支"作为会话属性 | 改为工作树属性 | 分支属于工作树；共享工作树即共享分支 |
| 进入/退出工作树模式 | 改为切换当前工作树 | 语义更直接 |
| `enter_worktree` / `leave_worktree` | 替换为 `switch_worktree` | 目标可以是主、新建或已有工作树 |
| 默认合并目标 = 基分支 | 改为主工作树当前 HEAD | 避免目标分支未检出的边界 |
| 工作树仅由会话独占 | 允许共享 | 多个会话可以绑定同一个工作树 |
| 工作树删除条件 | 增加"最后一个绑定"判断 | 共享工作树不能在别人还在用时删除 |

### 7.2 未采用的方案

- **cwd 固定在工作区根，Agent 用路径寻址工作树**：每次文件操作都要带工作树前缀，漏写就改到主工作树；不作为默认方案。
- **工作树只在提交/合并时临时使用**：编辑阶段仍在主工作树内，多个会话会先互相覆盖；不采用。
- **固定工作树池**：v1.7 已放弃，本版不再考虑。

### 7.3 保留的需求

轮次边界切换、依赖安装、工作树生命周期、分支切换、并发合并的 git 锁互斥与冲突处理、视图换根重载、文件写入审批保留、不额外限制 push/force、外部操作可见、只读 Git 视图、Git 优先、用户 Git 身份与系统凭据。

## 8. 实现基线（供实现参考，不构成验收标准）

### 8.1 工具契约

```ts
switch_worktree({
  target: "auto" | "main" | "new" | string,  // 自动复用/主工作树/新建/已有工作树路径
  base?: string,                              // 仅 target="new" 时有效
})
```

- `target: "auto"`：按 GIT-168 优先复用一个没有被其他打开会话绑定的链接工作树；没有可用工作树时新建一个托管工作树。不选主工作树。
- `target: "main"`：绑定主工作树。
- `target: "new"`：创建托管工作树与分支，记录 pending，边界生效。
- `target: <path>`：绑定已有链接工作树；路径必须在工作区内且存在于 `git worktree list`。
- 当前已绑定同一路径：返回 `already`。
- 目标被其他会话占用：`auto` 自动改用新建；显式路径返回 `taken`，Agent 可以改用 `new`。
- 成功返回 `{ status: "scheduled", worktree, branch, sharedWith: [...] }`，并记录内存中的 pending 状态。
- 空仓库且 `target: "new"`：返回 `unsupported: empty repository`。
- 工具描述必须包含：切换在本轮结束后生效；调用后不要继续修改文件；如果目标工作树已被其他会话绑定，说明会共享分支和文件。

### 8.2 边界执行顺序

1. 拿会话锁，暂停接受新消息。
2. 解析目标工作树；如果是新建且缺失则重建。
3. `dispose` 旧 `AgentSession`，用同一会话文件 `open` 并覆盖 cwd，`createAgentSession({ cwd })`。
4. 重新挂载审批扩展与计划扩展，重新订阅会话事件。
5. 用 `appendCustomMessageEntry` 写入切换记录。
6. 清 pending，释放锁，放行排队消息，通知渲染进程。

如果目标工作树与当前相同，跳过 2–6。

### 8.3 持久化结构

```json
{
  "version": 1,
  "worktrees": {
    "<worktreeId>": {
      "path": ".pi-workbench/worktrees/<worktreeId>",
      "managed": true,
      "branch": "pi/<worktreeId>",
      "base": "main",
      "createdBySession": "<sessionId>",
      "createdAt": "2026-10-26T00:00:00.000Z"
    }
  },
  "sessions": {
    "<sessionId>": { "worktree": "<worktreeId>" }
  }
}
```

主工作树用保留键 `"main"` 表示，不写入 `worktrees`。外部工作树写入 `worktrees`，`managed: false`。

### 8.4 SDK 与现状约束

- cwd 在 `createAgentSession` 时绑定，工具按 cwd 构建；bash 执行时读取 `sessionManager.getCwd()`。因此切换工作树必须重建运行时，不能只改一个字段；两个会话共享同一路径时不需要重建。
- 会话目录是全局的（`{agentDir}/sessions`），项目使用自定义 `sessionDir` 时，`SessionManager.list(cwd, sessionDir)` 和 `findById` 会按 header cwd 过滤。绑定链接工作树的会话，header 里的 cwd 可能是工作树路径，也可能仍是创建时的仓库根（切换使用 cwdOverride，不重写 header）；按 cwd 过滤不可靠。会话发现改为 `SessionManager.listAll(sessionDir)`，再用本工作区的 `session-git.json` 归组。
- **项目上下文发现**：`AGENTS.md` 从 cwd 沿祖先目录向上加载。工作树位于仓库根内部时，SDK 会把工作树自己的 `AGENTS.md` 视为主工作树副本的替代（shadow），只加载工作树里的版本；工作树缺少该文件时，祖先链会加载仓库根的版本。
- **`.pi` 项目资源**：`skills`、`prompts`、`themes` 只从 cwd 下的 `.pi` 读取，不沿祖先链查找。需要给资源加载器补上仓库根的 `.pi/*` 路径（可用 `resources_discover` 扩展事件），否则会话在链接工作树里会丢失仓库级技能与提示模板。`SettingsManager` 建议继续以仓库根为基准。
- **读写路径**：`read` / `write` 工具把相对路径解析到 cwd、绝对路径原样使用，没有 cwd 沙箱。cwd 就是当前工作树，相对路径不会落回主工作树。
- 链接工作树里不会有 `.env`、`.pi` 等未跟踪文件；按 GIT-118 的清单从主工作树复制。
- `.pi-workbench/worktrees` 必须通过 `.git/info/exclude` 排除，否则主工作树的 `git status` 会把它当成未跟踪目录。
- 同一分支同一时间只能被一个工作树检出；`git worktree add` 对空仓库会失败。
- 共享工作树的改动、切换分支、合并会同时影响所有绑定它的会话；所有相关会话头部必须在每轮结束后刷新。

## 9. 非目标

- 多仓工作区：一个工作区只能是一个 Git 仓库。
- 仓库发现、仓库选择器、仓库切换。
- 嵌套仓库与子模块的单独管理。
- 会话级别的分支独占（共享工作树时共享分支）。
- 实时协作编辑；会话之间读可见即可，冲突在合并时处理。
- Git 视图内的写操作（checkout、merge、rebase 等）。
- 自动提交；提交框、合并框等 Git 写操作 UI。
- 文件历史、行历史等按文件或按行的历史视图。
- LFS 的完整支持；按普通文件处理，不保证完整 Git 语义。
- 多用户或远程协作。
- 应用内 PR/MR 创建。
- 固定工作树池。
- 对 Agent 增加只读会话、分支归属锁、保护分支等硬限制。

## 10. 交付分期

**第一期（核心工作流）**

- 会话绑定主工作树、新建或复用链接工作树；
- 轮次边界切换工作树；
- 工作树创建、持久化、回收与崩溃清理；
- 依赖安装与复用；
- 分支切换；
- 提交与合并走对话；
- 视图、终端、全文搜索与聊天上下文跟随当前工作树。

**第二期（只读可视化）**

- 左侧只读 Git 视图：分支、工作树、提交历史、diff、比较、搜索、大仓库分页；
- GitHub PR/CI 状态；令牌在应用级设置中配置。

文件历史、行历史不在交付范围内。
