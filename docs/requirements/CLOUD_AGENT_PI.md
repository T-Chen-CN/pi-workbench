# Pi Workbench 云端 Agent 需求文档 v1（开发调度）

> **面向**：实现云端 Agent / 终端派活 / 云端通道的人
> **什么时候读**：动 `apps/cloud`、终端派活（device agent）、云端会话、工单状态机之前
> **什么时候要改**：角色边界、工单语义、可见性或验收场景变化时

**状态**：需求定稿，**未开工**（0.10.0 已移除旧的 Hermes 实现）  
**日期**：2026-11-19  
**范围**：云端 Agent 与终端 Agent 的**开发派活闭环** —— 提需求、定目标终端与仓库、出方案、确认、派活、跟进、汇报、停止  
**不包含**：日常助理（日程 / 笔记 / 搜索类）、服务器上跑开发、手机或 Web 客户端、多租户协作、云端 Web UI  
**历史**：0.8.0–0.9.1 的 Hermes 版云端 Agent 已于 0.10.0 整体移除（代码 / 文档 / 网关插件），本文档是重新设计的方案，不是它的延续

---

## 1. 背景与目标

### 1.1 现状

- 服务器性能与资源有限，**本地机器才是真实的开发环境**：仓库、私有依赖、内网服务、终端、Windows 专有环境都在本地。
- 0.10.0 已把旧的云端 Agent（Hermes 运行时 + 网关插件 + 云端工作区文件能力）整体移除，`pi-bridge` 的 `AgentManager` 与审批 / 计划 / 工作树扩展仍在，是可复用的内核资产。
- 所以不需要"在服务器上再养一个开发环境"，需要的是**调度**。

### 1.2 目标

1. 用户离开电脑时，仍能把开发任务交代出去，并且知道它在推进。
2. 云端 Agent 负责"想和协调"，终端 Agent 负责"动手"，两者的职责不重叠。
3. 用户不需要看执行细节：只要有进度感和一个可靠的停止按钮。

### 1.3 与本项目其它约束的关系

- 历史与导出的唯一真相源是会话记录（JSONL + `parentId` 分支），见 [ADR-003](../decisions/ADR-003-session-record-single-source.md)。云端会话与终端会话各自成立，**互不复制**。
- 权限是安全边界：`readonly` 用 deny 而不是 ask，审批超时与通道缺失一律拒绝（fail-closed）。见 [agent-runtime](../agent/agent-runtime.md)。
- 便携式目录与落盘位置遵循 [paths-and-storage](../agent/paths-and-storage.md)；新增运行时目录必须同步 `PROTECTED_TOP_LEVEL`。

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| **云端 Agent** | 跑在 VPS 上的 Agent 实例。会对话、出方案、派活、跟进、汇报；**没有** `bash` / `edit` / 读用户文件的工具 |
| **终端 Agent** | 跑在用户机器上的常驻 Agent（复用 `AgentManager`）。真正读写文件、跑命令、跑测试 |
| **工单（task）** | 派活的最小单位。自包含、有状态机、只投原设备、可取消 |
| **方案（plan）** | 云端的自然语言方案，含目标设备 / 仓库 / 分支。用户确认后成为授权范围 |
| **授权粒度** | 一次确认 = 授权该方案范围内的派活；换设备、换仓库、明显加码需重新确认 |
| **outbox** | 云端为每台设备维护的待投递队列（单调 `seq`），终端 `ack` 后清除 |
| **升级链** | 终端 → 云端 → 用户的三级决策上报路径 |

## 3. 核心模型

### 3.1 三个角色

| 角色 | 在哪 | 有仓库 | 能干什么 | 不能干什么 |
| --- | --- | --- | --- | --- |
| 用户 | 桌面 app | — | 提需求、定设备与仓库、确认方案、回答升级问题、停止工单 | 查看执行细节（不需要） |
| 云端 Agent | VPS 常驻 | ❌ | 对话、出方案、派活给指定终端、跟进、汇报、被下级问 | 读写文件、`bash`、`git`、看代码；替终端放权 |
| 终端 Agent | 每台机器常驻 | ✅ | 读文件、改代码、跑命令、跑测试 | 跨设备调度；自己扩权 |

### 3.2 主流程

```
① 用户提需求
② 用户与云端确认「目标终端 + 仓库 + 分支」        ← 方案的前提，先定
③ 云端出方案 ⇄ 聊到用户认可                       ← 唯一的授权闸门
④ 云端按方案派活（不再问设备、不逐次问）
⑤ 终端独立执行，里程碑回流；桌面端只显示"正在干活"
⑥ 云端跟进，必要时追加指令 / 升级请示
⑦ 云端汇报进展与结果
```

### 3.3 两级真相源

| 数据 | 真相源 | 另一方只存 |
| --- | --- | --- |
| 云端会话（需求、方案、工单引用、汇报、请示往来） | 云端（JSONL） | — |
| 终端会话（执行过程每一步） | **终端**（JSONL） | 云端存 `{deviceId, sessionId, commit}` 引用 |

云端**不缓存终端仓库内容**，最多缓存仓库路径与 remote 元信息。

## 4. 功能需求

### 4.1 配对与设备管理

- **F-01** 桌面端发起配对：云端下发一次性配对码 → 桌面端提交配对码 + 设备信息（名称、平台、仓库清单）→ 云端返回 `deviceId` 与长期 token。
- **F-02** **多设备**：不设单设备限制。云端维护设备清单，含名称、平台、仓库清单、最后活跃、在线状态。
- **F-03** Token 存储：云端只存 `SHA-256(token + salt)`，**不存明文**；终端把明文用 `safeStorage` 加密后落盘。
- **F-04** 终端缓存一份设备清单（`GET /v1/devices`），用于展示"云端登记了哪些设备"；断网时展示缓存副本并标注"可能过期"。
- **F-05** 解绑：云端删除哈希 → 该终端重连返回 401 → 终端提示"已被云端移除"并停止重试。
- **F-06** 仓库清单上报：终端上报本机可派活的仓库（绝对路径 + remote + 默认分支），不上报文件内容。

### 4.2 云端 Agent 配置

- **F-07** 桌面端提供「云端 Agent」设置页：模型、baseURL、API Key。
- **F-08** 配置经控制面推送到云端；云端 **AES-256-GCM 加密 at rest**，密钥来自服务器环境变量。
- **F-09** 日志、错误信息、异常堆栈里一律脱敏；UI 只显示掩码（末 4 位）。
- **F-10** 云端配置与本地配置**互不影响**（可以是不同模型）；可覆盖、可轮换，轮换对进行中的会话不中断（下一轮生效）。

### 4.3 方案与授权

- **F-11** 方案是自然语言，**不强制结构化 UI**；但方案必须显式写明：目标设备、仓库、分支、要做什么、怎么算完成。
- **F-12** **目标终端先定**：设备离线、或该设备上没有这个仓库 → 云端必须当场告知用户，**禁止静默换设备**。
- **F-13** 授权按方案粒度：用户确认后，云端可自主派活（含同一方案内连派多个工单），**不逐次请示**。
- **F-14** 超出已确认方案（换设备 / 换仓库 / 明显加码 / 新增目标）→ 云端必须重新征求确认。
- **F-15** 方案确认动作落进云端会话记录（谁在何时确认了什么），作为后续派活的授权凭据。

### 4.4 工单

- **F-16** 工单**自包含**：终端是另一个模型实例，看不到用户与云端的对话。

  ```
  deviceId                        已锁定，来自方案
  repo / workspace / baseBranch
  背景                            为什么做
  目标 + 验收标准                  怎么算完成
  允许改动范围                     越界必须停下来问
  禁止事项                         如：不许 force push、不许改 CI
  产出要求                         摘要 + 变更清单 + 测试结果 + diff（上限）
  是否提交 / 开 PR                 执行细节，由方案决定，不写死
  ```

- **F-17** 状态机：

  ```
  queued ──assign──▶ assigned ──accept──▶ running ──▶ done
    │                  │                   │    └──▶ failed
    │                  └──▶ rejected       ├──▶ waiting_human ──▶ running
    └──(TTL 到期)──────▶ expired            └──▶ cancelled
  ```

- **F-18** 可靠性：
  - 单设备**并发 1**；多设备可并行。
  - 重投**只投原设备**，以 `idempotencyKey` 去重；终端先落 `received` 再开工。
  - 取消必须**真 abort** 当前轮，不是只停推流。
  - 终端离线时工单留在 `queued`，有 TTL，到期变 `expired` 并汇报给用户。
- **F-19** 多设备是"方案里选谁"，不是自动路由；同一方案可拆多个工单派到不同设备（例如前端一台、后端一台）。

### 4.5 执行与升级链

```
终端 Agent ──决定不了──▶ 云端 Agent ──决定不了──▶ 用户
     ▲                        ▲                     │
     └──────── 答复下传 ───────┴────── 用户决定 ──────┘
```

- **F-20** 终端可向云端提问并**阻塞等待**；超时则进入 `waiting_human` 并**停手等**，禁止自行猜测继续改文件。
- **F-21** 云端回答不了 → 向用户请示；拿到答复后**继续推进 / 继续派活**，不需要用户重拍方案。
- **F-22** 每一级都有超时；超时一律 fail-closed（不放行、不默认同意）。
- **F-23** 请示与答复全部落进两边的会话记录，可回溯。

### 4.6 可见性与停止

用户**不看执行过程**，只看三样：

| 元素 | 内容 | 位置 |
| --- | --- | --- |
| 任务指示器 | 设备名 · 工单标题 · 状态（排队 / 执行中 / 等待决定 / 正在停止 / 已停止）· 已耗时 | **桌面端底部状态栏**（常驻一行，不弹面板） |
| 云端会话消息流 | 云端的自然语言汇报（里程碑、阻塞、完成、需要决定） | 聊天视图 |
| 结果汇报 | 摘要 + 变更清单 + 测试结果 + 引用（commit / diff 位置） | 聊天视图 |

- **F-24** **不提供**本地会话查看入口：不显示执行会话、不显示工具调用列表、不显示逐条 trace。
- **F-25** 终端会话记录**仍然保留在本地**（排障、审计、结果引用需要），只是没有 UI 入口；用户想了解细节只能通过云端 Agent 转述。
- **F-26** 停止：状态栏按钮 → 云端下发 `cancel` → 终端真 abort。UI 依次显示"正在停止 → 已停止"；终端离线时停止请求进 outbox，UI 显示"停止请求已排队"。
- **F-27** 停止的后果必须明说：**已改动的文件保留在工作区（不回滚）**，工单标 `cancelled`，云端汇报"停在第几步、改了哪些文件"。
- **F-28** 托盘角标可显示运行中工单数（P1，可选）；状态栏是唯一必需入口。

### 4.7 汇报

- **F-29** 主动汇报节点：派单时（派给谁、干什么）· 首个里程碑 · 阻塞或失败 · 完成 · 需要用户决定。
- **F-30** 汇报必须**可验证**：做了什么、改了哪些文件、测了什么、还剩什么、需要用户定什么；给 commit / 测试输出 / diff 位置，禁止只说"已完成"。

### 4.8 传输与可靠性

**定案：控制面 REST + 数据面单条 WebSocket。**

| 面 | 用途 | 形式 |
| --- | --- | --- |
| 控制面 | 配对换 token、下发云端 Agent 配置、上报仓库清单、拉设备清单、解绑 | HTTPS + JSON |
| 数据面 | 会话事件、工单生命周期、请示 / 答复、心跳 | 每台终端一条 WebSocket |

- **F-31** 终端**主动出站反连**云端（NAT 后不开放端口）。
- **F-32** 云端为每台设备维护 outbox：单调 `seq`，终端 `ack(seq)` 后删除；重连发 `resume(lastAckSeq)` 按序补投 —— 保证工单与取消不丢。
- **F-33** 会话事件沿用 `AgentTraceEvent` 帧（`text_delta` / `thinking_delta` / `tool_start` / `tool_update` / `tool_end` / `compaction`），**不复刻旧的 `/v1/runs`**。
- **F-34** 心跳 25s；空闲 60s 判定断线；重连指数退避 + 抖动（1s → 30s 封顶）。
- **F-35** SSE 长连接降级留到 P2，P0 不做。

### 4.9 数据与落盘

| 位置 | 内容 |
| --- | --- |
| 云端 | 设备清单（含 token 哈希）、云端会话 JSONL、outbox、工单状态、加密后的模型配置 |
| 终端 `data/cloud/` | 加密 token、`deviceId`、设备清单缓存、工单本地状态（`idempotencyKey` 台账） |
| 终端会话目录 | 执行过程会话（沿用现有会话管理，不新增目录语义） |

新增运行时目录必须同步 `PROTECTED_TOP_LEVEL`，否则更新会把目录当程序文件删掉。

## 5. 验收场景

| # | 场景 | 期望 |
| --- | --- | --- |
| A-01 | 新设备配对 | 配对码一次性有效；成功后云端与终端各持身份；重复使用配对码失败 |
| A-02 | 多设备 | 两台设备同时在线；云端设备清单两条；各自能接工单 |
| A-03 | 方案含目标终端 | 方案里显式写明设备 / 仓库 / 分支；设备离线时云端拒绝派活并告知用户 |
| A-04 | 确认后自主派活 | 用户确认方案后，云端连派 3 个工单，中途不再征求设备确认 |
| A-05 | 超范围派活 | 云端试图派到另一台设备 → 必须先征求确认，未确认则拒绝 |
| A-06 | 工单执行与汇报 | 状态栏显示"执行中"，云端在首个里程碑与完成时各汇报一次，内容含可验证引用 |
| A-07 | 终端提问 | 终端遇到歧义 → 云端答复 → 终端继续；云端答不了 → 问用户 → 答复下传后继续 |
| A-08 | 提问超时 | 终端阻塞等待超时 → 停在 `waiting_human`，**不改动文件** |
| A-09 | 停止 | 状态栏点停止 → 终端真 abort → 状态栏"已停止"，云端汇报停了在哪一步、改了哪些文件 |
| A-10 | 离线停止 | 终端离线时点停止 → 显示"停止请求已排队"；终端上线后先收到 cancel 再收到任何新工单 |
| A-11 | 断线续传 | 终端断网 2 分钟后重连 → 不重放旧事件、不丢断线期间的工单与取消 |
| A-12 | 幂等 | 同一 `idempotencyKey` 重投两次 → 终端只执行一次 |
| A-13 | 设备解绑 | 云端解绑设备 → 该终端重连 401，提示"已被云端移除" |
| A-14 | 配置轮换 | 桌面端换云端模型配置 → 云端下一轮生效，进行中的会话不中断，日志无明文 Key |
| A-15 | 过程不可见 | 任何界面都找不到"执行过程"入口；终端会话文件仍存在于本地 |
| A-16 | 真相源不串 | 云端会话记录中没有终端工具调用细节；终端记录中没有云端对话 |

## 6. 已确认的决策

| # | 决策 | 理由 / 后果 |
| --- | --- | --- |
| D-01 | 服务器上**不跑开发**：不 clone、不装依赖、不放仓库 | 服务器资源有限；本地才是真实开发环境 |
| D-02 | **工单级委派**，不做工具级远程代发 | 工具级代发要把云端循环挂在本机返回值上：延迟高、断线后状态半死、可靠性最难；工单级只需工单状态机 |
| D-03 | 云端 Agent **没有** `fs` / `bash` / `git` 工具 | 它没有仓库；给了只会变成"在服务器上瞎搞"。工具白名单写死 |
| D-04 | 授权按**方案粒度**，不逐次确认 | 用户要的是"方案认可后它自己干"，逐次确认等于没有自治 |
| D-05 | 目标设备与仓库在**方案阶段**锁定 | 派活时的设备选择是多余的决策；也让"要派到哪"可在方案里被用户直接看到 |
| D-06 | 多设备**不做自动路由** | 路由算法在没有明确收益的情况下增加不确定性；方案里显式指定更可预期 |
| D-07 | **不显示**终端执行会话，只留状态栏 + 停止 | 用户明确表示不需要看过程；黑盒 + 可靠中断反而更符合使用方式 |
| D-08 | 终端会话仍然本地留档 | 排障、审计、汇报引用都需要；"不展示"不等于"不记录" |
| D-09 | 云端配置由**桌面端上传** | 不需要在服务器上手工改文件；也让 Key 永远不写进仓库或部署脚本 |
| D-10 | 数据面选 **WebSocket**（控制面 REST） | 需要设备级双向 + outbox ack + 游标续传；SSE + POST 会把一条逻辑连接拆成两条腿 |
| D-11 | 只做**桌面端入口** | 手机 / Web 客户端会带来一整套 Web UI，是独立的大工程 |
| D-12 | 本期**不做日常助理** | 先把开发闭环跑通；助理工具集是另一条产品线 |

### 6.1 明确不采用

- 服务器上跑 Pi 开发会话（旧版"云端工作区"）。
- 使用旧 `/v1/runs` 协议与网关插件（插件仓库已删除）。
- 逐工具往返代发、工具级租约、工具级审计。
- 强制结构化方案编辑器。

## 7. 分期

| 期 | 内容 | 估时 |
| --- | --- | --- |
| **P0** | 云端会话 + 目标终端 / 仓库确认 + 方案闸门 + 6 个工具 + 工单状态机 + WS 通道与 outbox + 状态栏指示器与停止 + 三级升级链 + 汇报 + 配置下发 + 多设备配对 | 6–8 天 |
| **P1** | 追加指令 / 停止交互打磨 / 断线续传加固 / 结果 diff 回传 / 设备清单 UI / 历史工单极简列表 / 托盘角标 | 2–3 天 |
| **P2** | 提交与 PR / 多工单并行调度 / 失败重派 / SSE 降级 / 云端部署与自更新 | 2–3 天 |

云端 Agent 的 P0 工具白名单（**没有** `fs` / `bash` / `git`）：

```
list_devices()                   设备清单与在线状态
list_repos(deviceId)             该设备的仓库清单
dispatch_task({...self-contained}) → taskId
get_task(taskId)                 状态快照
wait_task(taskId, timeoutMs)     阻塞但有上限
send_task_message(taskId, text)  追加指令 / 纠偏
cancel_task(taskId)
```

## 9. 与旧 Hermes 实现的差异

| 维度 | 旧（0.8.0–0.9.1） | 本方案 |
| --- | --- | --- |
| 运行时 | 第三方 Hermes | Pi Agent（`AgentManager` 复用） |
| 服务器上的开发能力 | 有（云端工作区、文件读写） | **没有**，只有派活与助理类工具 |
| 派活语义 | 任务 + 租约 + 网关插件转发 | 工单级委派，云端直连终端 WS |
| 协议 | 自研 `/v1/runs` + SSE | 控制面 REST + 数据面 WS，帧用 `AgentTraceEvent` |
| 设备规模 | 单设备并发 1 | 多设备并行，单设备仍并发 1 |
| 用户可见性 | 内嵌控制台，可看执行细节 | 只看状态栏与汇报，**不展示过程** |
| 网关插件 | 独立 Python 仓库 | **不存在** |
