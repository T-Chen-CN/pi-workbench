# 报告与文档规范

> **面向**：要写分析报告或新增文档的人
> **什么时候读**：准备把结论落成文件、或判断"这事该不该写文档"时
> **什么时候要改**：报告流程或 `docs/` 目录结构变化时

> 索引：`docs/README.md` 是唯一入口，新增永久文档必须登记到那里。

## 什么时候写报告

**禁止创建报告**（直接做，简单告知结果）：

- 日常代码修复（修 bug、改 typo、格式调整）
- 单个文件的小改动
- 临时的分析或调查
- 批量文本替换、配置更新
- 即使用户说"详细检查"，也只在下面明确的条件成立时才写

**允许创建报告**（必须满足其中一条）：

1. 用户明确要求："生成报告"、"写成文档"、"需要审查记录"、"创建文档"
2. 架构重大决策：多工作区 / 多 Agent 的协调、技术选型改变、大型重构
3. 安全审计：安全漏洞、权限问题、数据处理风险
4. 里程碑归档：阶段完成总结（仅在用户明确指示时）

## 放哪里

```
docs/
├── reports/       # 临时分析报告（用户审查后删除或移动）
├── decisions/     # ADR：架构决策记录（永久）
├── architecture/  # 架构方案与数据流（永久）
├── agent/         # Agent 侧开发约束（永久，本目录）
├── guides/        # 构建、测试、打包（永久）
├── requirements/  # 需求文档（永久）
├── design/        # 设计系统（永久，唯一真相源）
└── progress/      # 进度与待办（永久）
```

- 临时报告：`docs/reports/{类型}-{日期}.md` 或 `{类型}-{主题}.md`。
- 永久文档：`{主题}.md`，放对应子目录，并登记进 `docs/README.md`。
- 决策用 ADR：`docs/decisions/ADR-00N-{主题}.md`，含背景 / 决策 / 备选 / 后果 / 落地位置 / 修订记录（参考 ADR-001 ~ ADR-003）。

## 生命周期

| 类型 | 处理 |
| --- | --- |
| `docs/reports/` 里的临时报告 | 用户审查后决定：移入永久目录（`decisions/` / `architecture/`）、整合进 `AGENTS.md` / `docs/progress/STATUS.md`，或直接删除 |
| 永久文档 | 版本控制保留；过期就改或删，不留副本 |

## 一条硬规则

改构建命令、目录结构、IPC 约定、数据落盘格式的提交，必须同 PR 更新对应文档。根 `AGENTS.md` 目标 ≤ 160 行：新增内容前先问"知道这条会不会改变 agent 的行为"，能从代码、`package.json` 或 `docs/` 读出来的，写指针而不是副本。
