# Agent 过程轨迹测试方案

> **面向**：要验收过程轨迹（thinking / 工具步骤 / Diff / 性能）的人
> **什么时候读**：改事件协议、AgentTrace 渲染或历史聚合之后
> **什么时候要改**：验收项或门禁变化时

> **适用版本**: Agent Trace v1（thinking / text / tool parts）
> **日期**: 2026-10-22
> **范围**: Electron 开发版、Web dev 模式、聊天历史、多会话、工具步骤与 Diff、性能与可访问性
> **关联**: [Agent 过程轨迹方案](../architecture/AGENT_TRACE.md)、[设计系统](../design/DESIGN_SYSTEM.md)、[Agent 测试清单](./AGENT-TESTING.md)

---

## 1. 测试目标

验证以下行为在真实模型输出和真实工具调用下成立：

1. thinking / text / tool 按真实发生顺序渲染，不再丢失中间正文。
2. 过程组始终默认收起；用户手动展开后保持展开。
3. 工具步骤显示状态、工具名、目标、耗时、参数与结果预览。
4. write/edit 能打开对应 Diff。
5. 历史恢复后顺序、工具状态与实时一致。
6. 多会话、长时间输出、停止/错误场景不破坏现有体验。
7. 没有 thinking / tool 的普通模型行为不变。

## 2. 环境与准备

### 2.1 基础环境

```bash
npm install
npm run dev        # 主验证环境：Electron + 真实工作区
npm run web:dev    # 辅助验证：Web dev 桥（SSE）
```

- Node.js ≥ 24
- Windows 优先验证；macOS/Linux 做冒烟
- 供应商：支持 thinking + tools 的模型（当前使用 `deepseek-flash`）
- 工作区：包含 `package.json`、`README.md`、可运行的测试脚本

### 2.2 测试前清理

- 新开一个空会话，避免旧历史干扰。
- 记录测试前的会话 ID 和工作区。
- 如需测试 write/edit，准备一个临时文件并在测试后删除：

```bash
echo "trace test" > agent-trace-test.md
```

### 2.3 日志与证据

| 证据 | 位置 |
| --- | --- |
| 主进程 / Agent / 渲染进程日志 | `logs/main.log`、`logs/agent.log`、`logs/renderer.log` |
| Pi 会话 JSONL | `data/agent/sessions/*.jsonl` |
| 会话标签 | `{workspace}/.pi-workbench/chat-tabs.json` |
| 截图 | Paper / Ink、1024 / 1440 宽度各一组 |

JSONL 中应能看到 `"type":"thinking"`、`"type":"toolCall"` 和 `toolResult`，用于核对历史恢复。

## 4. 手动测试用例

### A. 实时过程轨迹

#### A1 thinking → 正文

- **提示词**: `请先仔细思考，再回答：这个项目为什么采用 Electron？不要调用工具。`
- **步骤**: 发送后观察过程组标题与正文。
- **预期**:
  - 过程组默认收起，标题为 `思考中…`，状态点脉冲。
  - 思考结束后标题变为 `过程 · 思考 N 秒`，仍保持收起。
  - 正文按正常 Markdown 渲染；不出现重复的思考内容。
  - 手动展开后能看到思考正文；正文开始后不会自动收起。

#### A2 单个工具调用

- **提示词**: `读取 package.json，告诉我 name 和 version。`
- **预期**:
  - 过程组包含 `读取 package.json` 工具行。
  - 工具行状态从运行中 spinner 变为成功 Check，并显示耗时。
  - 组摘要显示工具数量；展开后可看到参数与结果预览。
  - 最终回答包含真实的 `name` 与 `version`。

#### A3 多工具与正文交替

- **提示词**: `先读取 package.json，再读取 README.md，然后总结项目。每一步前先用一句话说明你要做什么。`
- **预期**:
  - 时间线顺序为：说明文字 → 工具组 → 说明文字 → 工具组 → 最终总结。
  - 说明文字不会消失，也不会被最终回复覆盖。
  - 每个过程组独立收起；用户展开第一个组后，第二个新组仍默认收起。
  - 历史恢复后顺序完全一致。

#### A4 write / edit 与 Diff

- **前置**: 工作区存在 `agent-trace-test.md`。
- **提示词**: `请把 agent-trace-test.md 的内容改成三行：alpha、beta、gamma，然后读取确认。`
- **预期**:
  - 工具行显示 `修改` / `写入` 与文件路径。
  - 轮次结束后助手消息内出现本轮变更卡（不自动打开 Diff 面板），包含该文件。
  - 展开工具行并点击“查看修改”，能重新打开该文件的 Diff。
  - 结果预览不包含完整文件内容（只有截断摘要）。

#### A5 工具失败

- **提示词**: `请执行命令 node -e "process.exit(1)"，然后总结执行结果。`
- **预期**:
  - 工具行显示 danger 图标 + `执行失败` 文本，不是只靠颜色。
  - 组摘要包含 `1 个工具失败`，文字为 danger 色。
  - 应用不崩溃；Agent 能继续给出总结或错误说明。

#### A6 停止正在运行的工具

- **提示词**: `请执行命令 node -e "setTimeout(() => {}, 30000)"，执行完再回答。`
- **步骤**: 工具开始运行后点击“停止”。
- **预期**:
  - 停止后消息保留已经收到的思考 / 正文 / 工具 parts。
  - 仍在运行的工具以 `执行失败` 收尾，不会永远显示 spinner。
  - 不产生错误的“未读”或“完成”状态。

#### A7 脱敏思考（可选）

- **条件**: 使用会返回脱敏 thinking 的供应商 / 模型。
- **预期**:
  - 过程组内显示“该段思考已被供应商脱敏”。
  - 不显示加密签名或空内容。
  - 不会因为缺少 delta 而崩溃或无限等待。

#### A8 普通文本模型回归

- **条件**: 使用不支持 thinking 的模型，或提问不需要工具的问题。
- **提示词**: `只回复：ok`
- **预期**:
  - 不出现过程组；只显示普通 assistant 文本。
  - 现有的 Markdown、代码块复制、token 用量显示不变。

### B. 历史恢复与多会话

#### B1 重新打开历史会话

- **步骤**: 发送 A3 场景后关闭会话 / 重启应用，再打开同一会话。
- **预期**:
  - 思考、正文、工具行的顺序与实时一致。
  - 所有过程组默认收起；展开后内容完整。
  - 工具成功/失败状态与耗时保留（thinking 时长可能缺失）。
  - 历史恢复不自动播放脉冲或展开动效。

#### B2 多会话并行

- **步骤**: A 会话运行长输出；切到 B；再切回 A。
- **预期**:
  - A 的过程组状态和正文不丢失。
  - 切回 A 时过程组仍默认收起（除非之前手动展开过）。
  - 标签状态（运行中 / 未读 / 错误）正确。

#### B3 关闭正在运行的标签

- **步骤**: A 运行中关闭其标签，确认中止提示。
- **预期**:
  - 请求中止；已收到的 parts 不被写回已关闭会话。
  - 重新打开会话时，历史与 JSONL 一致。

#### B4 旧会话兼容

- **条件**: 选一个没有 parts 的旧会话（或旧 JSONL）。
- **预期**:
  - 自动降级为单条文本消息。
  - 不报错，不出现空过程组。

### C. 性能与稳定性

#### C1 长思考

- **提示词**: `请详细分析这个项目的聊天架构，输出不少于 2000 字的方案，不调用工具。`
- **预期**:
  - 过程组默认收起，主线程不被每 token 重渲染打满。
  - 输出期间切换会话、新建会话、输入框保持可响应。
  - 长思考展开后 Markdown 正常，不出现卡死。

#### C2 多工具长轨迹

- **提示词**: `依次读取 package.json、README.md、AGENTS.md，并总结。`
- **预期**:
  - 工具数量、失败数、耗时摘要正确。
  - 收起状态下 DOM 不挂载工具详情；展开才渲染。
  - 结果预览截断，不撑爆消息高度。

#### C3 快速切换与重复点击

- **步骤**: 在过程组标题、工具行上快速连续点击；切换会话后再回来。
- **预期**:
  - 展开/收起状态稳定，不出现闪烁或状态错乱。
  - 不产生控制台错误或 React key 警告。

#### C4 大结果预览

- **步骤**: 让工具返回较长输出（如读取大文件 / 长命令输出）。
- **预期**:
  - 结果预览最多约 2000 字符，超出显示省略提示。
  - 预览区域内部滚动，不撑开整个消息。
  - 不把完整文件内容通过 IPC 传输。

### D. 视觉、主题与可访问性

#### D1 Paper / Ink

- 在 Paper 与 Ink 下分别检查：过程组标题、思考正文、工具行、失败状态、结果预览。
- **预期**: 对比度符合设计系统；没有硬编码颜色或深色模式下的亮线。

#### D2 宽度

- 1024 与 1440 宽度下检查聊天列（含可拖拽宽度）。
- **预期**: 工具名、路径、耗时不会互相挤压；长路径可截断，结果预览不溢出。

#### D3 键盘与 ARIA

- 用 Tab 键依次聚焦过程组触发器、工具行。
- **预期**:
  - 触发器有 `aria-expanded` / `aria-controls`，Enter/Space 可展开。
  - 运行中内容有 `aria-busy`。
  - 工具行可见文本包含状态；失败不只靠颜色。
  - 焦点样式符合全局 accent 描边。

#### D4 动效不跟随系统偏好

- 开启系统 `prefers-reduced-motion: reduce`。
- **预期**: 动效不受影响（设计系统 v1.18 起始终播放）；状态仍可通过文字和图标识别。

#### D5 中英文

- 切换 zh / en。
- **预期**: 思考中、过程摘要、工具标签、参数/结果标题、错误文案全部翻译；不出现硬编码中文。

### E. Web dev 模式

- 使用 `npm run web:dev`，重复 A1 / A2 / A3。
- **预期**:
  - SSE `trace` 事件按顺序到达。
  - 过程组、工具行、结果预览与 Electron 一致。
  - 不出现“只有文本、没有思考和工具”的降级。

## 5. 已知限制（v1 当时的边界）

> `tool_update` 实时输出与历史 thinking 时长（E-06 / E-07）已于 2026-10-23 交付，下列前两条仅作回顾；当前能力以 [STATUS.md](../progress/STATUS.md) 为准。

- ~~`tool_update` 在 v1 未启用~~ → 已交付：工具执行中结果预览实时刷新。
- ~~thinking 时长仅实时可得~~ → 已交付：sidecar 记录历史时长。
- 工具行的“查看修改”只对当前轮次仍在 Diff 队列中的工具可用；历史工具行不保存 Diff 数据（2026-10-26 起明确不持久化）。
- 工具结果预览截断到约 2000 字符，完整内容仍在 Pi JSONL，UI 不提供全量查看器。（B-01，暂不排期）
- 脱敏 thinking 的占位取决于供应商是否返回 `redacted` / 空内容。（B-02，依赖供应商）
- 旧会话没有 `parts` 时按普通文本显示，不会补造过程轨迹。（B-03，不做）
